# @template/database

PostgreSQL access through Prisma 7 (driver adapter `@prisma/adapter-pg`, no Rust engine).

## Layout

| Path                             | Holds                                                                                                             |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `prisma/schema/schema.prisma`    | Generator and datasource only                                                                                     |
| `prisma/schema/<context>.prisma` | Models owned by one bounded context                                                                               |
| `prisma/migrations/`             | SQL migrations, generated by `bun run db:migrate`, never edited after merge                                       |
| `prisma.config.ts`               | Prisma CLI config; loads the root `.env`                                                                          |
| `src/database.module.ts`         | `DatabaseModule.forRoot()`: `PrismaService`, transactions, `UnitOfWork` binding                                   |
| `src/client/`                    | `PrismaService`                                                                                                   |
| `src/transactions/`              | `PrismaTransactionHost` (AsyncLocalStorage-scoped transaction client, inject in repositories), `PrismaUnitOfWork` |
| `src/testing/`                   | `resetDatabase()`: exported as `@template/database/testing`                                                       |
| `src/generated/`                 | Prisma client output (git-ignored, built by `nx run database:prisma-generate`)                                    |

## Rules

- Repositories use `host.tx`, never `PrismaService` directly, so they join the
  surrounding `UnitOfWork.run()` transaction.
- A context's tables are touched only by that context's infrastructure layer.
- Commands: `bun run db:generate`, `bun run db:migrate` (dev), `bun run db:deploy` (CI/prod).
- `nx run database:prisma-check-drift` fails when the schema has changes no migration holds
  (CI runs it): edit a `.prisma` file, then `bun run db:migrate`.
