# The worker transcodes on scratch disk

[ADR 0013](./0013-files-live-in-one-bucket-and-browsers-upload-directly.md) keeps files off the local disk; transcoding is the one exception. ffmpeg needs a seekable input (an MP4 or MOV may keep its index after the media data) and a seekable output (the index is moved to the front so playback starts at once), so the worker downloads the Source into a fresh directory under `MEDIA_SCRATCH_DIR`, encodes there, uploads the result to the bucket and removes the directory whatever happens. Nothing on that disk is ever read by another request or survives a job: the bucket stays the only place files live, and a worker can be replaced at any time. The disk must hold a Source and its Playable file at once, a few gigabytes for a long 4K video; one transcode runs at a time per worker, as an encode already uses every core.
