# Files live in one bucket, split by context, and browsers upload to it directly

Files go to S3-compatible object storage (RustFS locally, any S3 API in production) through `@template/storage`, never to the database or the local disk, so every replica sees the same files. Like the database ([ADR 0009](./0009-one-database-schema-split-by-context.md)), there is one bucket and each context owns a key prefix (`identity/…`), written only by its infrastructure layer; keys are never reused, so objects can be cached forever. Browsers send files straight to the bucket with a presigned form whose policy pins the key, type and size, and the api checks what arrived (size, declared type, file signature) before keeping it: uploads cost the api no bandwidth and no request timeout, and an unchecked file is never referenced. Unclaimed uploads sit under `staging/`, which the bucket expires after a day. Reading happens through presigned URLs, so the bucket stays private. Storage is reported by readiness, not required: its outage breaks file features, not sign-in.
