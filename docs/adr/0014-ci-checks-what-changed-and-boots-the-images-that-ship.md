# CI checks what changed, boots the images that ship, and gates merges on one check

A `Plan` job asks Nx which projects a change affects and every other job checks only those: lint, typecheck, unit tests and build run in parallel, integration and each e2e suite get their own runner and infrastructure, and only the affected apps' images are built. A change outside every project (the workflows, the compose stack, `.env.example`) checks everything, since it can break any suite. Each image is booted against Postgres, Redis and RustFS until its readiness probe answers, then scanned: the e2e suites run the apps from source, so only this proves the artifact that ships starts, with nothing pruned from it. The committed OpenAPI document and the migrations are checked against what generates them (`api:openapi`, `database:prisma-check-drift`), so neither can drift from the code. Branch protection requires one job, `CI OK`, which fails when any job failed and passes when a job was skipped for having nothing to check: the required checks never change as jobs are added, and a documentation change does not wait for an e2e run. Releases follow the Conventional Commits the pipeline enforces: release-please derives the version and changelog, and publishing pushes attested images to GHCR (see [the guide](../guides/cut-a-release.md)).
