# Docker runs every service on fixed addresses, hardened and distroless in production

Two compose files at the root, `docker-compose.dev.yaml` and `docker-compose.prod.yaml`, run the same services from images under `docker/<env>/images/` with config under `docker/<env>/config/`; production adds the migrator, nginx and cloudflared. Every service has the same fixed address on 192.168.250.0/24 in both files (`*_IP` in `.env`), so one `.env` names the servers in either environment, and Postgres can admit clients by address (`pg_hba.conf`). Containers get no env_file: each service lists, under `environment:`, only the `.env` keys its config schema reads, so a compromised web or nginx holds no database password or JWT secret. In production nothing is published: cloudflared dials out to Cloudflare, every public hostname reaches nginx, and nginx routes on the Host header's first label (`api.`, `s3.`, else web) from a static file. Every production container runs as non-root, with a read-only root filesystem, every Linux capability dropped and no privilege escalation, because none of them needs one: volumes take their owner from the image, and nginx listens on 8080. Images are distroless except the database's, because `initdb` needs `/bin/sh`: the official Postgres image runs as `postgres` from the start instead. Values the topology fixes (`TRUST_PROXY`, `COOKIE_SECURE`, `NODE_ENV`) are set in the compose file, not taken from `.env`, so a development `.env` cannot weaken production.

## Consequences

- An address lives in `.env` and, for some, in `docker/prod/config/nginx/nginx.conf` and `docker/prod/config/database/pg_hba.conf`: change them together. The dev and prod stacks cannot run on one host at once (same subnet).
- Bridge addresses are reachable from the host on Linux only. On Docker Desktop, tools run on the host use the localhost ports the dev file publishes (127.0.0.1 only), not the `.env` addresses.
- Distroless images have no shell: healthchecks are exec form (`bun -e`, `redis-cli`, a static `probe` binary for nginx and RustFS), and a binary that links a library the base lacks (Prisma's schema engine, argon2's addon) gets it copied from the same Debian release at build time.
- A new `.env` key reaches a container only once added to that service's `environment:`.
- `tools/scripts/smoke-test-stack.ts` boots the whole production stack and checks each route through nginx; CI runs it whenever the Docker setup changes ([ADR 0014](./0014-ci-checks-what-changed-and-boots-the-images-that-ship.md)).
